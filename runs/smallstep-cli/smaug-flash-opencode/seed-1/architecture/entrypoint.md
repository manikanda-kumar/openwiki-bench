# Runtime Entrypoint and Command Routing

The `step` binary is small: `cmd/step/main.go` sets global identity strings and
calls `cmd.Run()`. All command wiring lives in `internal/cmd/root.go`, which
constructs an `urfave/cli` application and registers every command package via
blank imports.

## Process entry

`main()` calls `step.Set("Smallstep CLI", Version, BuildTime)` and
`ca.UserAgent = step.Version()` (so the CA module reports the CLI's UA), then
`cmd.SetName(AppName)`. `Run()` invokes `run()`, which exits with its integer
result.

`run()` first calls `step.Init()` to set up the step environment (base path,
contexts), then `newApp(os.Stdout, os.Stderr)` and `app.Run(os.Args)`. Any
non-nil error from `app.Run` is printed to stderr and the process returns exit
code 1; otherwise it returns 0 (`internal/cmd/root.go`).

## App construction and command registry

`newApp` wires framework components:

- Default PEM/JOSE password prompters so file writing prompts match CLI UI.
- Help/version templates and printers from `cli-utils/usage`.
- An `EnableBashCompletion` app with a `--config` flag.

Commands are registered by blank-importing the top-level command packages
(`command/api`, `command/base64`, `command/ca`, `command/certificate`,
`command/completion`, `command/context`, `command/crl`, `command/crypto`,
`command/fileserver`, `command/oauth`, `command/path`, `command/ssh`, and
`command/beta`). Each package's `init()` calls `command.Register(cmd)` (from
`cli-utils/command`), and `app.Commands = command.Retrieve()` assembles the
final command tree (`internal/cmd/root.go`).

## Plugin dispatch

When `step` is run with a first argument that is not a built-in command,
`app.Action` looks up a matching plugin executable `step-<name>-plugin` via
`plugin.LookPath` and runs it; otherwise it shows command help for the name or
the app help. If the name is a known plugin (e.g. `kms`), an error suggests its
download URL (`internal/cmd/root.go`).

`plugin.LookPath` searches `$STEPPATH/plugins` (or PATH) and handles Windows
extensions (`internal/plugin/plugin.go`).

## Shell auto-completion

`step completion` prints the bash, zsh, and fish completion scripts. Bash and
zsh are embedded strings driving `--generate-bash-completion`; fish is
generated by `urfave/cli` (`command/completion/completion.go`). The cli app
enables bash completion globally.

## Error handling, STEPDEBUG, and exit codes

Errors carrying a `Message()` interface are formatted specially; otherwise the
raw error is printed. In both cases:

- When `STEPDEBUG=1`, the full error stack is written to stderr.
- Otherwise a concise message is printed and the user is told to re-run with
  `STEPDEBUG=1` for more info.

Exit codes:
- 0 on success.
- 1 on any command error.
- 1 on `step.Init()` failure.
- 2 on a recovered panic (unless `STEPDEBUG=1`, in which case the panic is
  re-raised for a full traceback).

The `panicHandler` (deferred in `run`) prints the version, release date, and a
suggested `STEPDEBUG=1 …` command before exiting 2. `utils.Fail` provides a
convenience that prints an error and exits 1, honoring `STEPDEBUG`
(`utils/utils.go`, `internal/cmd/root.go`).

## Root command test

`internal/cmd/root_test.go` verifies that `newApp` assembles the expected set
of top-level commands (`help`, `api`, `base64`, `fileserver`, `path`,
`certificate`, `completion`, `context`, `crl`, `crypto`, `oauth`, `version`,
`ca`, `beta`, `ssh`), guarding that registration wiring stays stable.
