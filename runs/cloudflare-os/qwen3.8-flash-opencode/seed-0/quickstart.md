# Quickstart

Prerequisite: **pnpm** (the workspace pins `packageManager: pnpm@11.17.0`, package.json:6). npm won't understand the workspace/catalog setup.

## Run the whole stack locally

```
pnpm run-local          # then open http://localhost:8787
```

What that actually does (scripts/run-local.ts:3-14, 35-42): installs dependencies, then builds **only what's needed to run** through the vp task cache — `@gadgets/typed-storage#build` (the backend imports its built `dist`) and `@gadgets/workshop-frontend#build:assets` (the SPA bundle) — and launches `scripts/run-dev-server.ts --serve-frontend-assets`, which serves the built SPA as static assets from the backend on `localhost:8787`. It notably does *not* run the full `pnpm build`: gatekeeper configurator and SPA bundles are generated by `run-dev-server.ts` at startup, not prebuilt here. It runs the entire stack on local `wrangler`/`workerd`; data persists in the `.wrangler` subdirectory (README.md:20-30, 184-194). The README's suggested first prompts: slides for a meeting, a collaborative whiteboard, tic-tac-toe, a GitHub issue dashboard (needs GitHub configured) (README.md:34-43).

## The split dev loop (hacking on it)

Two terminals (README.md:220-228, "Developing"):

```
pnpm dev-server         # workers under wrangler; backend at localhost:8787
pnpm dev-client         # Vite dev server; open http://localhost:3000
```

- **Dev server:** `scripts/run-dev-server.ts` builds the gatekeeper configurator and app bundles first, then starts `wrangler dev` and watchers; the port comes from `--port` or `VITE_BACKEND_HOST` (default `localhost:8787`) (scripts/run-dev-server.ts:9-12; scripts/dev-server-config.ts:34-67). It synthesizes the `GATEKEEPER_*` service bindings and, for OAuth connectors, seeds each gatekeeper's `CLIENT_ID`/`CLIENT_SECRET` from shared shell vars — `GITHUB_CLIENT_ID`/`GITHUB_CLIENT_SECRET`, `GOOGLE_*`, `CLOUDFLARE_OAUTH_*` (scripts/run-dev-server.ts:408-413; docs/oauth-signin.md:54-62).
- **Dev client:** Vite serves on **port 3000** with `/api/client-errors`, `/blueprint-screenshot`, `/api/site-logo` proxied to the backend host (packages/workshop-frontend/vite.config.ts:81-88). The dev router worker (same code as production `packages/router`) also proxies frontend requests when no assets binding is present (packages/router/src/index.ts:8-9, 42-56).

Optional: `--use-workers-ai-binding` (passthrough to the dev server) exercises the gateway binding transport. For a production-style deployment there is an online wizard at `os.cloudflare.app/deploy` plus the cloudflare-os-starter repo (README.md:176-182).

## Commands you'll actually run

| Task | Command | Notes |
|---|---|---|
| Type-check + codegen everything | `pnpm build` | = `vp run -r --cache build`; replays from cache when untouched (package.json:8) |
| One package's build | `vp run -F <package> build` | `pnpm --filter` can't see tasks ([Build System and Toolchain](/openwiki/development/build-tooling.md)) |
| All tests | `pnpm test` | root `node --test scripts/**` + per-package cached `test` tasks (package.json:10) |
| One package's tests | `pnpm --filter <pkg> test:run` (fast, while iterating) / `vp run -F <pkg> test` (cached) | [Testing Strategy](/openwiki/development/testing.md) |
| Lint (what CI enforces) | `pnpm lint` | oxlint via `vp lint` + scripts typecheck + full build (package.json:20-24) |
| Regenerate worker types | `pnpm types:generate` | wrangler types per package, post-processed ([Build System](/openwiki/development/build-tooling.md)) |
| Clean cached outputs | `pnpm clean` | package.json:17 |

Run `pnpm lint` (which includes `build`) before pushing — that's what CI gates (CONTRIBUTING.md:12-15).

## Workspace tour

- `packages/workshop-shared` — the RPC contracts (`api.ts`, `gatekeeper.ts`); read these first ([RPC Contract](/openwiki/architecture/rpc-contract.md)).
- `packages/workshop-backend` — the kernel Worker; `overseer.ts` is the workspace DO (~11k lines — navigate by region, see [Overseer](/openwiki/architecture/overseer-workspace.md)).
- `packages/workshop-frontend` — the SPA; `packages/router` — the public origin.
- `packages/gatekeeper-*` — one Worker per external service; each README is its vendor-app setup guide ([Catalog](/openwiki/integrations/gatekeeper-catalog.md), [Guide](/openwiki/guides/adding-a-gatekeeper.md)).
- `docs/` — design writeups (blueprints, oauth-signin, sharing, integration-testing); `plans/` — historical plans. Source and tests are authoritative; these are context.
