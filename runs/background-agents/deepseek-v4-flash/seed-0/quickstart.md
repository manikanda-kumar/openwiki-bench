# Open-Inspect Repository Wiki — Quickstart

Open-Inspect is a **single-tenant background coding agent system** (inspired by [Ramp's Inspect](https://builders.ramp.com/post/why-we-built-our-background-agent)): a hosted agent that spawns sandboxed dev environments to work on GitHub repositories while you focus on something else. The system is arranged in three tiers — web client → Cloudflare control plane (Durable Objects + D1) → sandbox data plane — with three Hono bot workers (slack-bot, github-bot, linear-bot) on the client edge. This page is the task-routing map: it tells you which wiki folder answers which kind of question, where the major subsystems live, and which invariants must survive any change.

## The canonical prompt/data flow

> **User prompt → client (web or bot) → control plane session DO (WebSocket) → sandbox bridge → OpenCode agent → streaming events back through the same WebSocket chain.**

Everything in this repo either serves this path, extends it (child sessions, automations, PRs), or observes it (bots, webhooks, analytics). Trace any change against this chain before writing code:

1. Client opens a WebSocket to the session's DO, or a bot calls the control plane API.
2. The DO enqueues the prompt on the durable message queue; if no sandbox is running, one is spawned or restored from a snapshot/prebuilt image.
3. The sandbox bridge receives the prompt (with author info for commit attribution) and feeds the OpenCode server.
4. OpenCode generates tool calls and token streams; each action emits events.
5. Events stream back through the bridge WebSocket, are persisted in the DO's SQLite, and are broadcast to all connected clients (multiplayer sees identical state because state lives in the control plane).

Control plane composition points that matter when tracing a change: `src/index.ts` (worker entrypoints), `src/router.ts` (API dispatcher), `src/session/durable-object.ts` (DO adapter) → `src/session/components.ts` (`createSessionRuntime`, the eager composition root), and `src/sandbox/lifecycle/manager.ts` (`SandboxLifecycleManager`, injectable decisions + side effects).

## Top invariants (verify before and after any change)

- **Build order**: always build `@open-inspect/shared` before any package that imports it (`control-plane`, `web`, `slack-bot`, `github-bot`, `linear-bot`) — enforced by the root `build`/`typecheck` scripts, which run the shared package first.
- **Durations**: milliseconds in TypeScript with `_MS` suffix (e.g. `INACTIVITY_TIMEOUT_MS`), seconds in Python with `_seconds` suffix (e.g. `DEFAULT_SANDBOX_TIMEOUT_SECONDS = 7200` in `src/sandbox/provider.ts`); **never use a bare `timeout`** (AGENTS.md convention).
- **Single-tenant security model**: all users share one GitHub App installation scope and can access any repository the App can reach; the system performs **no per-user repository access validation** at session creation. GitHub users' OAuth tokens are used only for PR creation (with the bot as fallback); git clone/fetch/push auth is a shared App installation token brokered server-side to sandboxes on demand. Never add per-user repo-gating logic without a deliberate, documented exception.
- **State split**: the session's authoritative aggregate lives in the DO-embedded SQLite (`session/schema.ts` `SCHEMA_SQL`); D1 is the global listing/index/config mirror. Route handlers must use the instrumented `ctx.db` handle, never the raw `env.DB` binding (ESLint-enforced under `src/routes` and `src/webhooks`).
- **Fail fast, never degraded**: provider and SCM factories are constructed eagerly in `createSessionRuntime` and throw on misconfigured deployments; encryption keys are validated eagerly (`env-validation.ts`); a misconfiguration fails session init before any sandbox spawn.
- **Sandbox lifecycle state is authoritative across WebSocket reconnects**: losing the sandbox WebSocket does not stop the sandbox — the bridge reconnects while the control plane schedules a heartbeat check; explicit lifecycle paths (inactivity, stale heartbeat) persist `stopped`/`stale` before closing, which prevents reconnection.
- **D1 is written before the DO is initialized** when creating a session; failures must be caught before any sandbox spawn.
- **`repo_owner` may contain `/`** (GitLab subgroups) — only `repo_name` is a single path segment. Use the shared repository-identity helpers; split on the last `/` and encode the owner as one API route segment.

## Which source files are authoritative for each domain

- **Control plane entrypoints**: `packages/control-plane/src/index.ts` — `fetch` (API + WebSocket upgrade), `scheduled` (per-minute automation/scheduler tick, image-build cron, abandoned-draft sweep), `queue` (image-build finalization consumer, GitHub Autofix queue).
- **API surface**: `src/router.ts` + `src/routes/*.ts` — routes carry per-route authentication policies (public, user, service sig1, sandbox token); `src/routes/shared.ts` defines the route primitives and request context.
- **Session DO**: `src/session/durable-object.ts` (platform adapter), `src/session/components.ts` (composition root), `src/session/schema.ts` (SQLite schema).
- **Sandbox lifecycle**: `src/sandbox/lifecycle/decisions.ts` (pure policy), `src/sandbox/lifecycle/manager.ts` (side effects, `isSpawningSandbox` flag), `src/sandbox/provider.ts` (provider interface + capabilities), `src/sandbox/provider-factory.ts`.
- **Secrets/auth**: `src/auth/` (GitHub App token minting in `github-app.ts`, sig1 service auth, browser auth), `src/db/scoped-secrets.ts`/`repo-secrets.ts`/`global-secrets.ts`/`environment-secrets.ts` (encrypted at rest with AES-256-GCM).
- **Automations**: `src/automation/`, `src/scheduler/scheduler.ts`, `src/webhooks/` (automation-event, github, sentry, slack), `packages/shared/src/triggers/` (types, conditions, registry).
- **Sandbox runtime (Python)**: `packages/sandbox-runtime/src/sandbox_runtime/entrypoint.py` (composition root), `supervisor.py` (lifecycle/restart policy), `bridge.py` (WebSocket), `opencode_server.py`, `repository_sync.py`, `git_signing.py`, `diff_capture.py`/`diff_collector.py`, `managed_skills.py`, `repo_config.py` (parses `/`-joined owners, `is_safe_repo_owner`).
- **Shared types/contracts**: `packages/shared/src/types/` — session API, server messages, sandbox events, automations, environments, skills, session-diffs, provider-accounts, boundary schemas.

## Engineering conventions to follow

- **Conventional commits** (`feat:`, `fix:`, `docs:`, `refactor:`, `chore:`, `test:`), subject under 72 characters.
- **Durations** carry their unit in the name (see invariants); define each default value exactly once in a named constant and import it everywhere; do not restate literal values in comments.
- **Git in sandbox code** is always invoked with argument arrays — repository paths and filenames are never interpolated into a shell command.
- **PKCS#8 format** is required for Cloudflare GitHub App private keys (`openssl pkcs8 -topk8 -inform PEM -outform PEM -nocrypt`).
- **New Durable Object bindings** need a two-phase Terraform deploy (`enable_durable_object_bindings = false`, then `true`); there is no checked-in `wrangler.toml` — config is Terraform-generated.
- **Testing**: TS packages use co-located Vitest; control-plane integration tests run in a workerd pool (Miniflare + real D1, shared per-file instance — call `cleanD1Tables()`); Python uses pytest + pytest-asyncio. D1 migrations under `terraform/d1/migrations/` (currently 70 numbered SQL files) are applied automatically in the integration pool.
