# Benchmark documentation brief

Create a source-grounded wiki for engineers who must understand, operate, debug, and safely change this repository.

- Explain the architecture, ownership boundaries, core data/control flows, persistence, external integrations, configuration, and failure handling.
- Include a practical quickstart and focused change guides for representative maintenance tasks.
- Treat source code and tests as authoritative. Cite concrete source evidence for every non-obvious technical claim.
- State uncertainty when the repository does not establish a fact. Do not invent runtime behavior, guarantees, or deployment details.
- Prefer a coherent, non-overlapping taxonomy over exhaustive file-by-file narration.
