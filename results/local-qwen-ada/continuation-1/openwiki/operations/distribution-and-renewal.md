# Distribution, Renewal, and Operational Integration

The operational surface of the CLI: how the binary is packaged and distributed (Docker images, GoReleaser archives/packages, Windows PowerShell installer), how certificates are renewed automatically via systemd units and timers, the hidden `step fileserver` command, shell completion, and the testscript-based integration test harness.

## Docker images

`docker/Dockerfile` is a multi-stage build. The builder stage uses `golang:alpine` cross-compiling for `TARGETOS`/`TARGETARCH`/`TARGETVARIANT` (mapping `TARGETVARIANT` to `GOARM` on `arm`), then runs `CGO_ENABLED=0 GOOS_OVERRIDE=... make V=1 bin/step`, consistent with the Makefile's default `CGO_ENABLED=0`. The final stage is `alpine`, creates a non-root `step` user (uid/gid 1000 by default via `STEPUID`/`STEPGID`), sets `ENV STEP=/home/step` and `STEPPATH=/home/step`, copies `bin/step` to `/usr/local/bin/step`, and runs `CMD ["/bin/bash"]` with `STOPSIGNAL SIGTERM`. `docker/Dockerfile.debian` is the same layout on `golang:trixie`/`debian:trixie` (apt-installed `make git curl` and `curl jq`).

## GoReleaser, Debian, and Windows packaging

Release builds are defined in `.goreleaser.yml` (`pro: true`, `project_name: step`). The `default` build compiles `./cmd/step` with `CGO_ENABLED=0`, `-trimpath`, and ldflags `-w -X main.Version=... -X main.BuildTime=...` across a target matrix (darwin, linux, freebsd, windows amd64/arm64, arm 5/6/7, mips, ppc64le) into `bin/step`; a second `nfpm` build produces the same binary named `step-cli` for packages. `nfpms` builds `.deb` and `.rpm` packages (`package_name: step-cli`, `bindir: /usr/bin`, vendor Smallstep Labs) with `scripts/postinstall.sh` and `scripts/postremove.sh`: postinstall registers the `update-alternatives` link `/usr/bin/step` (priority 50) and writes `step completion bash` output to `/usr/share/bash-completion/completions/step`; postremove removes the alternative. Packages embed `debian/copyright` at `/usr/share/doc/step-cli/copyright`. Note the repo's `debian/` directory contains only `changelog` and `copyright` (no `debian/control`); package metadata is generated by GoReleaser, and `debian/changelog` points to the GitHub releases page. Artifacts are checksummed (`checksums.txt`), signed with cosign (`sign-blob` with sigstore bundles on all artifacts), and published to an S3 bucket (`AWS_S3_BUCKET`) and GCP Artifact Registry via `scripts/package-upload.sh` / `scripts/package-repo-import.sh` (gcloud, `gs://artifacts-outgoing/`). `scripts/package-upload.sh` deliberately skips `armhf6` `.deb` uploads due to a GCP Artifact Registry conflict. Release notes link `dl.smallstep.com` artifacts and show a `cosign verify-blob` verification example.

`powershell/install-step.ps1` downloads `step.exe` and `uninstall-step.ps1` from `https://dl.smallstep.com/s3/cli/s3-windows-installer/` into `$env:ProgramW6432\Smallstep Labs`, adds that directory to the Machine `Path`, and enables the `ssh-agent` service (set to Automatic and started).

## Automatic renewal: systemd units and timers

`systemd/` ships template units for automatic renewal:

- `cert-renewer@.service` (oneshot, root) with `Environment=STEPPATH=/etc/step-ca`, `CERT_LOCATION=/etc/step/certs/%i.crt`, `KEY_LOCATION=/etc/step/certs/%i.key`. It uses `ExecCondition=/usr/bin/step certificate needs-renewal ${CERT_LOCATION}` (run only when renewal is due), then `ExecStart=/usr/bin/step ca renew --force ${CERT_LOCATION} ${KEY_LOCATION}`, and `ExecStartPost` attempts `systemctl try-reload-or-restart %i` on the relying service. It is `PartOf=cert-renewer.target`.
- `cert-renewer@.timer` fires `OnCalendar=*:1/15` (every 15 minutes) with `Persistent=true`, `AccuracySec=1us`, and `RandomizedDelaySec=5m` jitter to avoid a thundering herd; `WantedBy=timers.target`.
- `ssh-cert-renewer.service` (oneshot, root) renews the local SSH host certificate: `STEPPATH=/etc/step`, `CERT_LOCATION=/etc/ssh/ssh_host_ed25519_key-cert.pub`, `KEY_LOCATION=/etc/ssh/ssh_host_ed25519_key`; `ExecCondition=/usr/bin/step ssh needs-renewal ${CERT_LOCATION}`, `ExecStart=/usr/bin/step ssh renew --force ${CERT_LOCATION} ${KEY_LOCATION}`, and `ExecStartPost` reloads/restarts `sshd.service`. The unit comments note ECDSA is also usable but Ed25519 is the default key shown.
- `ssh-cert-renewer.timer` uses the same 15-minute calendar schedule.
- `cert-renewer.target` is a convenience target to restart all certificate renewers.

`systemd/README.md` points to the Smallstep "Automating Certificate Renewal" docs and notes these files are redirect targets in the `files.smallstep.com` S3 bucket; moving them in the repo requires updating those redirects.

## step fileserver

`command/fileserver/fileserver.go` registers a hidden, explicitly experimental command: `step fileserver <dir>` starts an HTTP(S) server serving a directory, "only intended for test purposes" (e.g. ACME webroot-style hosting). Flags: `--address` (default `:0`), `--cert`, `--key`, `--roots` (client CA for mutual TLS; requires `--cert` and `--key`), and `--pidfile`. With `--cert`/`--key` it serves HTTPS with `MinVersion` TLS 1.2; `--roots` enables `tls.RequireAndVerifyClientCert`. A `tlsRenewer` supports reloading the certificate/key/roots on `SIGHUP` via `GetConfigForClient`; `SIGINT`/`SIGTERM` trigger a 5-second graceful `http.Server.Shutdown`. The command is enabled by the blank import `_ "github.com/smallstep/cli/command/fileserver"` in `internal/cmd/root.go`.

## Shell completion

`command/completion/completion.go` registers `step completion <shell>` (bash, zsh, fish), printing embedded completion scripts (e.g. append `step completion bash` to `~/.bash_completion`). The top-level `autocomplete/` folder (`bash_autocomplete`, `zsh_autocomplete`) is deprecated per `autocomplete/README.md` in favor of `step completion`.

## Integration test harness

`integration/` is a `testscript`-based harness. `integration/shared_test.go` defines `TestMain`, which registers the `step` command as an in-process script command via `testscript.Main(m, map[string]func(){"step": cmd.Run})` using `internal/cmd` — tests run the CLI in-process rather than a separately built binary. `integration/main_test.go` covers `step version` (expecting `Smallstep CLI/0000000-dev` in test context) and unknown-command failure. `integration/certificate_test.go` generates CSRs and test CAs (`keyutil`, `minica`, `pemutil`) and script-tests `step certificate sign` (valid and bad-CSR cases), `verify` (valid and bad-PEM cases), and `fingerprint`, with a custom `check_certificate` testscript command that parses a certificate bundle from stdout. `integration/crypto_test.go` script-tests the `crypto` group: JWK commands (inspect, create RSA/EC/OKP/Oct), JWT, key pair, OTP, and help. `integration/help_test.go` checks root `--help` output and a help-quality report: it unmarshals a `usage.Report` and asserts headline consistency against expected sections, per-section word/line thresholds, and no `TODO` strings.

## Uncertainties

- External release infrastructure (the `AWS_S3_BUCKET` S3 blob store, `dl.smallstep.com` CDN, GCP Artifact Registry, and the cosign signing identity) is referenced by config but lives outside the repo; its behavior is not verifiable here.
- The `debian/` directory has no `control` file, so the exact deb/rpm control metadata is only implied by `.goreleaser.yml` nfpms fields.
