# SSH Certificate Subsystem

The `step ssh` command group creates and manages SSH user and host certificates, integrates with the local SSH agent, and renders CA-provided SSH client/server configuration. It is registered from `command/ssh/ssh.go:26` and backed by the SSH helpers in `internal/sshutil/` and the CA client flows in `utils/cautils/`.

Unlike `step certificate`, which works with X.509 certificates, this group requests SSH certificates through the `SSHSign`, `SSHRenew`, `SSHRekey`, and `SSHRevoke` CA APIs using one-time SSH tokens generated by the certificate flow (`utils/cautils/certificate_flow.go:207`).

Shared flags are defined in `command/ssh/ssh.go:106`: `--principal/-n`, `--host`, `--host-id`, `--sign`, `--password-file`, `--provisioner-password-file`, `--add-user`, and `--private-key`. The principal flags document that they cannot be combined with `--token` for OIDC, JWK, and X5C provisioners, or provisioners with `disableCustomSANs`, because those provisioners derive principals from the token (`command/ssh/ssh.go:107`).

When the subject is an email address, `createPrincipalsFromSubject` (`command/ssh/ssh.go:298`) builds the default principals: the sanitized subject, the local part of the email (when different), and the original subject.

Several commands wrap failures in user-facing error helpers: `sshConfigErr` suggests running `step ssh config`, `contactAdminErr` suggests contacting an administrator, and `debugErr` reports an internal step process error (`command/ssh/ssh.go:273`).

## `step ssh certificate`

`certificateAction` (`command/ssh/certificate.go:221`) takes two positional arguments, `<key-id>` and `<key-file>`, and derives the SSH file conventions `<key-file>.pub` and `<key-file>-cert.pub` (`command/ssh/certificate.go:229`).

Key behavior:

- `--host` selects `provisioner.SSHHostCert` with `cautils.SSHHostSignType`; otherwise a user certificate with `cautils.SSHUserSignType` is requested (`command/ssh/certificate.go:295`).
- `--sign` signs an existing public key file instead of generating a key pair, and `--private-key` supplies the matching private key so the pair can be added to the agent (`command/ssh/certificate.go:318`).
- Flag validation rejects `--no-password` without `--insecure`, `--no-password` with `--password-file` or `--min-password-length`, `--token` with `--provisioner-password-file`, `--host` with `--add-user`, `--host-id` without `--host`, and `--add-user` with more than one principal (`command/ssh/certificate.go:266`).
- When the CA requires client authentication, an X.509 identity CSR is created with `ca.CreateIdentityRequest`. For host certificates the identity must carry a URI SAN containing the host UUID: an explicit `--host-id` UUID is used, `--host-id machine` derives one from `/etc/machine-id`, or the UUID is read from a pre-existing default identity certificate to avoid clobbering the host ID on re-runs (`command/ssh/certificate.go:371`, `command/ssh/certificate.go:377`).
- `--add-user` generates an extra key pair and requests an add-user provisioner certificate alongside the user certificate; the result is written to `<base>-provisioner`, `<base>-provisioner.pub`, and `<base>-provisioner-cert.pub` (`command/ssh/certificate.go:437`, `command/ssh/certificate.go:502`).
- Generated private keys are written OpenSSH-format with mode `0600`, encrypted with a prompted password unless `--no-password` with `--insecure` or `--password-file` is used; public keys and certificates are written `0644` as authorized keys with the subject as comment (`command/ssh/certificate.go:466`, `command/ssh/certificate.go:491`).
- Unless `--no-agent` is passed, a user certificate plus private key is added to the SSH agent with the subject as comment (`command/ssh/certificate.go:529`).

`deriveMachineID` maps `/etc/machine-id` to a version-4 UUID via a keyed Blake2b-128 hash (`command/ssh/certificate.go:559`), and `readExistingUUID` recovers the host UUID from the first URI of the default identity certificate (`command/ssh/certificate.go:583`).

## `step ssh login` and `logout`

`loginAction` (`command/ssh/login.go:114`) requires a running SSH agent (`command/ssh/login.go:155`). If the agent already holds a key with the subject comment signed by one of the CA's user certificate keys, it prints a notice and returns; `--force` bypasses this check (`command/ssh/login.go:161`). Otherwise it generates a key pair, generates an SSH user sign token, and calls `SSHSign`; when the CA requires client authentication it also writes the X.509 identity certificate to the default identity location. The signed certificate and private key are added to the agent via `Agent.AddCertificate` (`command/ssh/login.go:286`), and `--add-user` additionally adds the add-user provisioner certificate.

`logoutAction` (`command/ssh/logout.go:78`) removes keys from the agent. `--all` with no argument removes every key in the agent; otherwise it removes keys matching the subject comment, restricted to keys signed by the CA's user certificate keys when the roots can be fetched, or to certificate keys when they cannot. `removeSSHKeys` dispatches between `Agent.RemoveKeys` (with subject) and `Agent.RemoveAllKeys` (`command/ssh/logout.go:145`).

## `step ssh config`

`configAction` (`command/ssh/config.go:112`) renders SSH configuration from templates stored in the CA. It supports:

- `--host` to configure an SSH server instead of a client.
- `--roots` to print the user (or `--host` host) CA public keys in authorized-key format, and `--federation` to print all keys in the federation; both error with a "not configured with SSH support" message when the CA returns no keys (`command/ssh/config.go:164`).
- `--team` to bootstrap a team authority before fetching templates (`command/ssh/config.go:137`).
- `--set key=value` and `--set-file` template variables (`command/ssh/config.go:213`).

For user config the `User` template variable is taken from `--set`, or derived from the first principal of a CA-signed certificate in the agent; the command fails with "ssh certificate not found: please run `step ssh login <identity>`" when neither is available (`command/ssh/config.go:223`). The request is sent to `client.SSHConfig` with the user or host cert type, and the returned `HostTemplates` or `UserTemplates` are written to disk (or printed with `--dry-run`); the template data includes `GOOS`, `StepPath`, `StepBasePath`, the SSH template version `v2`, the current context name, and `Console` (`command/ssh/config.go:201`).

## `step ssh hosts` and `check-host`

`hostsAction` (`command/ssh/hosts.go:50`) calls `client.SSHGetHosts` and prints a tab-separated `HOSTNAME ID TAGS` table; the documented contract is exit status 0 when the server exists. `checkHostAction` (`command/ssh/checkHost.go:61`) calls `client.SSHCheckHost` for a hostname, prints `true`/`false` with `--verbose`, and exits 1 when no certificate exists. When the CA requires client authentication it builds an X.5C one-time token for the `/ssh/check-host` audience from the default identity (`command/ssh/checkHost.go:81`).

## Renew, rekey, and revoke

SSH renewal, rekey, and revocation all use one-time SSH tokens whose type selects the CA endpoint (`utils/cautils/token_flow.go:27`):

| Constant | Endpoint |
| --- | --- |
| `SSHUserSignType` / `SSHHostSignType` | `/1.0/ssh/sign` |
| `SSHRenewType` | `/1.0/ssh/renew` |
| `SSHRekeyType` | `/1.0/ssh/rekey` |
| `SSHRevokeType` | `/1.0/ssh/revoke` |

`renewAction` (`command/ssh/renew.go:76`) is for host certificates only (per its description, it cannot renew user certificates). It reads the certificate serial number, sets `sshpop-cert`/`sshpop-key` on the context so the flow can build an SSHPOP token keyed by the serial, calls `caClient.SSHRenew`, and writes the new certificate to `--out` (defaulting to overwriting the input certificate) plus any renewed identity certificate (`command/ssh/renew.go:96`).

`rekeyAction` (`command/ssh/rekey.go:80`) additionally generates a new default key pair and calls `caClient.SSHRekey` with the new public key, writing the new private key (OpenSSH, `0600`, password-prompted or `--password-file`), the public key, and the new certificate (`command/ssh/rekey.go:138`).

`revokeAction` (`command/ssh/revoke.go:124`) takes a serial number, or derives it from `--sshpop-cert` when no argument is given, maps `--reasonCode` to an OCSP code via `cmdca.ReasonCodeToNum`, and calls `caClient.SSHRevoke` with `Passive: true` (`command/ssh/revoke.go:186`).

## `step ssh needs-renewal`

`needsRenewalAction` (`command/ssh/needsRenewal.go:81`) parses the certificate file and reports whether renewal is needed based on remaining lifetime. `--expires-in` accepts either a percent threshold (default `66`, the `defaultPercentUsedThreshold` at `command/ssh/needsRenewal.go:20`) of lifetime used, or a duration window; `--verbose` prints a human-readable affirmation. The documented exit codes are 0 (needs renewal), 1 (does not), 2 (file missing), and 255 (other errors) (`command/ssh/needsRenewal.go:168`).

The bundled `systemd/ssh-cert-renewer.timer` runs every 15 minutes with a 5-minute randomized delay and drives `systemd/ssh-cert-renewer.service`, whose `ExecCondition` invokes `step ssh needs-renewal ${CERT_LOCATION}` so the renewal (`step ssh renew`) only runs when the check passes (`systemd/ssh-cert-renewer.service:20`, `systemd/ssh-cert-renewer.timer:9`).

## `step ssh proxycommand`

`proxycommandAction` (`command/ssh/proxycommand.go:70`) is designed to be used from an SSH client `ProxyCommand` directive with `<user> <host> <port>` arguments. It first ensures the user is logged in (`doLoginIfNeeded` checks the agent for a valid CA-signed key and, if absent, performs the full login flow and adds the certificate to the agent, `command/ssh/proxycommand.go:100`), then asks the CA for the configured bastion via `client.SSHBastion` (`command/ssh/proxycommand.go:218`).

- Without a bastion it opens a direct TCP connection and copies stdin/stdout in both directions, returning as soon as either direction completes to avoid a deadlock when the server closes first (`command/ssh/proxycommand.go:233`).
- With a bastion it execs the local `ssh` binary (falling back to `/usr/bin/ssh`, `command/ssh/proxycommand.go:28`) with the bastion user, port, and flags, appending either a bastion command rendered by `sshutil.ProxyCommand` (which substitutes `%%`, `%h`, `%p`, and `%r`) or an `nc host port` connector (`command/ssh/proxycommand.go:266`).

## `step ssh inspect`, `list`, and `fingerprint`

`inspectAction` (`command/ssh/inspect.go:59`) reads a certificate file or STDIN, falls back from `ssh.ParseAuthorizedKey` to raw base64 `ssh.ParsePublicKey` parsing, and prints either a `text` layout (type, public key, signing CA, key ID, serial, validity, principals, critical options, extensions, and hex signature blob) or JSON produced by `sshutil.InspectCertificate` (`command/ssh/inspect.go:109`).

`listAction` (`command/ssh/list.go:62`) lists the agent's keys, filtered by an optional subject comment, printing fingerprints by default or raw authorized keys with `--raw`. `fingerprint` (`command/ssh/fingerprint.go:54`) prints the fingerprint of a public key or certificate using `go.step.sm/crypto/sshutil` formatters, with `--format` (default `base64-raw`) and `--certificate` mode flags.

## `internal/sshutil`

### Agent client

`Agent` (`internal/sshutil/agent.go:85`) wraps `ssh/agent.ExtendedAgent` with the connection. `DialAgent` uses `SSH_AUTH_SOCK`: Unix sockets on Unix platforms (`internal/sshutil/agent_unix.go:14`), and Unix sockets, Windows pipes at `SSH_AUTH_SOCK`, or the default OpenSSH pipe `\\.\pipe\openssh-ssh-agent` (overridable via an `IdentityAgent` line in `~/.ssh/config`) on Windows (`internal/sshutil/agent_windows.go:16`, `internal/sshutil/pipe.go:11`).

Agent operations take variadic `AgentOption` filters:

- `WithSignatureKey(keys)` keeps only certificates signed by the given keys (`internal/sshutil/agent.go:32`).
- `WithCertsOnly()` keeps only keys that parse as certificates (`internal/sshutil/agent.go:55`).
- `WithRemoveExpiredCerts(t)` transparently removes certificates whose `ValidBefore` has passed (`internal/sshutil/agent.go:65`).

The methods built on these options are `HasKeys`, `ListKeys`, `ListCertificates`, `GetKey`, `GetSigner`, `RemoveKeys`, and `RemoveAllKeys` (`internal/sshutil/agent.go:107`). `AddCertificate` adds a certificate with the subject as comment, computing the lifetime from `ValidBefore` (infinite certificates use lifetime 0, already-expired ones are rejected, and Windows always uses 0 because the Windows agent fails with a lifetime) (`internal/sshutil/agent.go:245`). `AuthMethod` exposes the agent as an `ssh.AuthMethod` via a public-keys callback (`internal/sshutil/agent.go:102`).

### Key parsing and conversion

- `NewCertSigner` builds an `ssh.Signer` that signs with the certificate (`internal/sshutil/sshutil.go:22`).
- `ParseCertificate` parses marshaled bytes into an `*ssh.Certificate` (`internal/sshutil/sshutil.go:35`).
- `PublicKey` converts an `ssh.PublicKey` to a `crypto.PublicKey`, dispatching by key type to RSA, ECDSA (including SK-ECDSA), Ed25519 (including SK-Ed25519), and the insecure DSA legacy type (`internal/sshutil/sshutil.go:48`).
- The low-level parsers `parseRSA`, `parseECDSA`, `parseED25519`, and `parseDSA` follow RFC 4253 and RFC 5656 wire formats; `parseECDSA` uses `crypto/ecdh` to build the key from the point bytes (`internal/sshutil/sshutil.go:138`).
- `publicKeyTypeAndSize` maps key types to display names and bit sizes, appending `-CERT` for certificates, and is used by certificate inspection (`internal/sshutil/sshutil.go:68`).

### Certificate inspection

`InspectCertificate` (`internal/sshutil/inspect.go:42`) converts an `*ssh.Certificate` into a `CertificateInspect` with the certificate type (`host`, `user`, or `unknown`), key and signing-key algorithm plus SHA-256 fingerprints, serial, validity, principals, critical options, extensions, and the raw signature. `Validity` renders `from ... to ...` in local time with the same layout as `ssh-keygen`, or `forever` for infinite certificates (`internal/sshutil/inspect.go:93`).

### Shell

`Shell` (`internal/sshutil/shell.go:102`) is a small remote-execution client used by the step certificate authority tooling. `NewShell` dials the address (defaulting the port to 22) using `~/.ssh/known_hosts` as the host key callback; auth methods default to the SSH agent and can be replaced with `WithAuthMethod`, `WithSigner`, or `WithCertificate` (`internal/sshutil/shell.go:111`). It supports `Run` (one-shot command), `RemoteShell` (PTY with terminal-size detection), `LocalForward`, and `RemoteForward` port forwarding (`internal/sshutil/shell.go:161`).

## Change guides

### Adding a new `step ssh` subcommand

1. Create `command/ssh/<name>.go` exporting a `<name>Command() cli.Command` with a `command.ActionFunc` action, following the structure of `command/ssh/needsRenewal.go:22`.
2. Reuse the shared flags from `command/ssh/ssh.go:106` (`sshPrincipalFlag`, `sshHostFlag`, `sshHostIDFlag`, `sshSignFlag`, `sshPasswordFileFlag`, `sshProvisionerPasswordFlag`, `sshAddUserFlag`, `sshPrivateKeyFlag`) and the global CA flags from `flags`.
3. Register the command in the `Subcommands` list in `command/ssh/ssh.go:84`.
4. For CA operations, build the one-time token with `flow.GenerateSSHToken` using the appropriate `utils/cautils` token type (adding a new type to the constants in `utils/cautils/token_flow.go:27` and its audience mapping in the same file's `parseAudience` if the CA endpoint is new), then call the matching `caClient.SSH*` API.
5. When the command talks to the agent, use `sshutil.DialAgent` and the `AgentOption` filters rather than the raw `ssh/agent` API.

### Extending `internal/sshutil`

1. Add new key-type handling in `PublicKey` and `publicKeyTypeAndSize` (`internal/sshutil/sshutil.go:48`), with a dedicated wire parser alongside `parseRSA`/`parseECDSA`/`parseED25519`/`parseDSA` and unit tests in `internal/sshutil/sshutil_test.go`.
2. Add new agent behaviors as `AgentOption` functions (`internal/sshutil/agent.go:29`) so they compose with the existing `HasKeys`/`ListKeys`/`GetKey`/`RemoveKeys` paths, keeping the `options` struct fields private.
3. Platform-specific agent dialing belongs in the build-tagged `agent_unix.go`/`agent_windows.go` files; keep the public entry point `DialAgent` in `internal/sshutil/agent.go:92`.
